## 1. מטרה

להבטיח ששינויים במערכות, בתשתית ובתוכנה של Celox AI מנוהלים באופן מבוקר, למזעור סיכון אבטחה ושיבוש שירות.

## 2. סיווג שינויים

| סוג | הגדרה | דוגמאות |
|-----|-------|---------|
| **סטנדרטי** | שינויי שגרה מאושרים-מראש, בסיכון נמוך | עדכוני תלויות, שינויי תוכן, כוונוני ממשק |
| **רגיל** | שינוי מתוכנן הדורש סקירה | פיצ'ר חדש, שינוי סכימת מסד נתונים, אינטגרציה חדשה |
| **חירום** | תיקון דחוף לבעיה קריטית | תיקון אבטחה, תיקון אירוע P1, תיקון השחתת נתונים |

## 3. תהליך השינוי

### 3.1 שינויים סטנדרטיים
- ניתן ליישם ללא אישור נוסף
- חייבים commit ל-Git עם הודעת commit תיאורית
- נפרסים דרך צינור CI/CD סטנדרטי (GitHub → פריסה אוטומטית ב-Vercel)
- מאומתים בייצור תוך 30 דקות מהפריסה

### 3.2 שינויים רגילים
1. **תכנון:** לתעד את השינוי, הסיבה, המערכות המושפעות, תוכנית rollback
2. **סקירה:** סקירה עצמית להשלכות אבטחה (הזרקת SQL, עקיפת אימות, חשיפת מידע)
3. **בדיקה:** לבדוק בסביבת פיתוח
4. **אישור:** אישור מנכ"ל/ממונה אבטחה (יכול להיות אישור עצמי למפעיל יחיד)
5. **פריסה:** לפרוס דרך CI/CD בחלון תעבורה נמוכה
6. **אימות:** לוודא פריסה מוצלחת ולבדוק פונקציונליות מרכזית
7. **תיעוד:** לעדכן תיעוד רלוונטי

### 3.3 שינויי חירום
1. ליישם את התיקון מיידית לפתרון הבעיה הקריטית
2. לתעד מה שונה ולמה (תוך 24 שעות)
3. לבצע סקירה שלאחר שינוי תוך 5 ימי עסקים
4. לעדכן את מרשם הסיכונים אם נוצלה פגיעות חדשה

## 4. ניהול שינויי מסד נתונים

שינויי סכימה דורשים זהירות מיוחדת:
- כל שינויי הסכימה מנוהלים דרך Supabase migrations
- migrations חייבות בדיקה מול עותק של מבנה נתוני הייצור לפני היישום
- שינויים שוברים (הסרת עמודה, שינויי סוג) דורשים תוכנית migration רב-שלבית
- מדיניות RLS חייבת סקירה לאחר שינויי סכימה כדי לוודא שבידוד הנתונים נשמר
- תוכנית rollback חייבת להיות מתועדת לפני הביצוע

## 5. ניהול תלויות

- כל תלויות ה-npm נעולות דרך `package-lock.json`
- עדכוני תלויות נסקרים להתראות אבטחה לפני העדכון
- Dependabot של GitHub או סקירה ידנית לניטור תלויות פגיעות
- תיקוני אבטחה קריטיים מטופלים כשינויי חירום

## 6. ניהול תצורה

- כל תצורת האפליקציה נשמרת במשתני סביבה של Vercel
- משתני סביבה לעולם אינם מוכנסים לקוד המקור
- שינויים במשתני סביבה מתועדים עם התאריך והסיבה
- משתני סביבה של ייצור נסקרים רבעונית

## 7. בקרת גרסאות

- כל שינויי הקוד נשמרים ב-GitHub
- ענף `main` מוגן — שינויים נפרסים מ-`main`
- הודעות commit לפי הפורמט: `type(scope): description`
- תגי Git משמשים לשחרורי ייצור
