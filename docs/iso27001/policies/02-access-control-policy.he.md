## 1. מטרה

מדיניות זו מגדירה דרישות לבקרת גישה למערכות המידע, לנתונים ולתשתית של Celox AI, כדי להבטיח שרק אנשים מורשים ניגשים למשאבים המתאימים לתפקידם.

## 2. היקף

מכסה כל גישה אל:
- אפליקציית הווב של Celox AI (celoxai.com)
- מסד הנתונים והאחסון ב-Supabase
- תשתית הפריסה ב-Vercel
- מאגר קוד המקור ב-GitHub
- חשבון Cloudflare
- לוחות בקרה ניהוליים ו-APIs

## 3. עקרונות בקרת גישה

### 3.1 הרשאות מינימום
כל משתמש, תהליך ומערכת מקבלים את הגישה המינימלית הנדרשת למילוי תפקידם. ללא חריגים.

### 3.2 צורך-לדעת
גישה למידע רגיש ניתנת רק לבעלי צורך עסקי מתועד.

### 3.3 הפרדת תפקידים
במידת האפשר, פונקציות קריטיות מופרדות כך שאדם יחיד אינו יכול להשלים פעולה רגישה לבדו. כאשר לא ניתן (חברת אדם-אחד), נעשה שימוש בבקרות מפצות (לוגי ביקורת).

### 3.4 אפס הרשאות קבועות
גישה מיוחסת (מנהל, root למסד נתונים) אינה מוחזקת דרך קבע. היא נרכשת רק בעת הצורך ומשוחררת מיד לאחר מכן.

## 4. ניהול חשבונות משתמש

### 4.1 הקצאת חשבונות
- כל חשבונות המשתמש נוצרים בידי מנהל המערכת
- חשבונות דורשים הצדקה עסקית מתועדת
- כל משתמש מקבל חשבון ייחודי — חשבונות משותפים אסורים
- חשבונות חדשים כפופים לאימות אימייל

### 4.2 דרישות אימות
| מערכת | דרישת מינימום |
|-------|---------------|
| אפליקציית Celox AI | אימייל + סיסמה (8 תווים לפחות) + CAPTCHA של Cloudflare Turnstile |
| לוח בקרה Supabase | סיסמה חזקה + MFA (TOTP) |
| GitHub | סיסמה חזקה + MFA (עדיף מפתח חומרה) |
| לוח בקרה Vercel | סיסמה חזקה + MFA |
| לוח בקרה Cloudflare | סיסמה חזקה + MFA |

### 4.3 דרישות סיסמה
- 8 תווים לפחות (מומלץ 12+)
- שילוב אותיות גדולות, קטנות, מספרים וסימנים
- ללא שימוש חוזר משירותים אחרים
- נשמרת רק כ-hash מסוג bcrypt המנוהל ע"י Supabase — לעולם לא כטקסט גלוי
- מוחלפת מיד עם חשד לפריצה

### 4.4 אימות רב-גורמי (MFA)
MFA הוא חובה לכל החשבונות הניהוליים (Supabase, GitHub, Vercel, Cloudflare). אפליקציית Celox AI מציעה MFA כאפשרות למשתמשים, ותהפוך אותו לחובה לחשבונות ברמת master בגרסה עתידית.

### 4.5 ביטול חשבונות
- חשבונות לקוח מושבתים עם סיום ההתקשרות
- הגישה מוסרת תוך 24 שעות מהודעת הסיום
- חשבונות מבוטלים מתועדים בלוג

### 4.6 סקירת גישה תקופתית
זכויות הגישה נסקרות רבעונית. חשבונות שאינם בשימוש (ללא כניסה 90 יום) מושבתים עד לסקירה.

## 5. בקרת גישה ברמת האפליקציה

### 5.1 בקרת גישה מבוססת-תפקיד (RBAC)
האפליקציה מיישמת RBAC עם התפקידים הבאים:

| תפקיד | רמת גישה |
|-------|----------|
| `master` | מנהל חברה מלא — ניהול כל המשתמשים, הרכבים, הנהגים והאינטגרציות |
| `manager` | ניהול נהגים ורכבים; ללא ניהול משתמשים או חיובים |
| `viewer` | גישת קריאה בלבד לנתונים המשויכים |

### 5.2 בידוד חברות
כל הנתונים מבודדים לפי חברה באמצעות מדיניות Row Level Security (RLS) ב-PostgreSQL. משתמשי חברה א' אינם יכולים לגשת לנתוני חברה ב' בשום מצב. ה-RLS נאכף ברמת מסד הנתונים באמצעות הפונקציה `my_company_id()`.

### 5.3 גישת API
- כל קריאות ה-API דורשות אסימון סשן JWT תקף של Supabase
- אסימוני JWT פגים לאחר 8 שעות (בהתאם לפסק-זמן הסשן)
- נקודות קצה של webhook (קליטת GPS) משתמשות באסימוני webhook ייחודיים לכל חברה
- אישורי אינטגרציה נשמרים מוצפנים באמצעות pgcrypto (AES-256)

## 6. גישה פיזית

Celox AI Ltd. פועלת כחברת ענן ללא שרתים מקומיים. גישה פיזית מבוקרת ע"י:
- מרכזי נתונים של AWS (דרך Supabase) — מוסמכים ISO 27001 ו-SOC 2
- אין שרתים אישיים או חומרה מקומית בהיקף

תחנת העבודה הראשית (מחשב נייד מפתח) חייבת להיות:
- מוגנת בהצפנת דיסק מלאה (BitLocker או FileVault)
- ננעלת ב-PIN/סיסמה לאחר 5 דקות של חוסר פעילות
- לא מושארת ללא השגחה במקומות ציבוריים

## 7. גישה מרחוק

- כל הגישה למערכות ייצור היא דרך HTTPS (TLS 1.2+)
- אין צורך ב-VPN — כל גישה מאומתת בשכבת האפליקציה
- גישת SSH לכל שרת אסורה (תשתית מנוהלת-ענן בלבד)

## 8. ניטור ותיעוד

- כל ניסיונות ההתחברות (הצלחה וכישלון) מתועדים ע"י Supabase Auth
- ניסיונות התחברות כושלים מפעילים התראה לאחר 5 כשלים רצופים
- לוגי ביקורת נשמרים ל-12 חודשים לפחות
