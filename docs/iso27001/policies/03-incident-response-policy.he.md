## 1. מטרה

להבטיח גישה עקבית ואפקטיבית לניהול אירועי אבטחת מידע, למזעור השפעה עסקית, להגנה על נתוני לקוחות, ולעמידה בחובות הדיווח החוקיות.

## 4. תהליך התגובה לאירוע

### שלב 1: זיהוי ודיווח (0–1 שעות)

**מקורות זיהוי:**
- התראות אנומליה של Supabase Auth
- התראות פריסה של Vercel
- דיווחי לקוח דרך privacy@celoxai.com
- אירועי אבטחה של Cloudflare
- התראות סריקת סודות של GitHub

**עם הזיהוי:**
1. לתעד את האירוע במרשם האירועים (תבנית למטה)
2. לשייך סיווג חומרה ראשוני
3. להודיע למנכ"ל/ממונה האבטחה מיידית ב-P1/P2

### שלב 2: הכלה (1–4 שעות ל-P1/P2)

**פעולות הכלה מיידיות לפי חומרה:**

**P1 – קריטי:**
- [ ] לבטל את כל הסשנים הפעילים (Supabase Auth: sign-out לכולם)
- [ ] להחליף מפתחות וסודות API שנפרצו
- [ ] להפעיל מצב קריאה-בלבד במסד הנתונים במידת הצורך
- [ ] להוריד את הפריסה ב-Vercel במידת הצורך
- [ ] לשמר את כל הלוגים לפני כל שינוי
- [ ] לא למחוק או לשנות ראיות

**P2 – גבוה:**
- [ ] להשבית חשבון/ות משתמש מושפעים
- [ ] להחליף את האישור הספציפי שנפרץ
- [ ] לחסום IP חשוד דרך Cloudflare
- [ ] להגביר ניטור

**P3/P4:**
- [ ] לתעד ולנטר
- [ ] לתקן או להגדיר לפי הצורך

### שלב 3: חקירה (תוך 24 שעות ל-P1)

1. לקבוע את שורש הבעיה
2. לזהות את כל המערכות והנתונים המושפעים
3. לקבוע אם נחשף מידע אישי (מפעיל חובת דיווח)
4. לתעד ציר זמן של האירועים
5. לשמר ראיות להליכים משפטיים אפשריים

### שלב 4: דיווח

#### דיווח ללקוח
- אם אומתה חשיפת נתוני לקוח: להודיע ללקוחות המושפעים תוך **72 שעות** (לפי תקנות הגנת הפרטיות 2017)
- ההודעה תכלול: מה קרה, אילו נתונים הושפעו, מה אנו עושים, ומה הלקוחות יכולים לעשות

#### דיווח רגולטורי
| רגולטור | סף | מועד |
|---------|-----|------|
| הרשות להגנת הפרטיות | כל דליפת מידע אישי | 72 שעות `[לאימות עו"ד תחת תיקון 13]` |
| CERT-IL | פריצה הפוגעת בתשתית לאומית | בהקדם האפשרי |

### שלב 5: מיגור והתאוששות

1. להסיר את שורש הבעיה (תיקון, ביטול, הגדרה מחדש)
2. לשחזר מגיבוי נקי במידת הצורך
3. לוודא שלמות מערכת לפני החזרה לפעילות
4. להחזיר גישה למשתמשים מושפעים
5. להגביר ניטור לאחר התאוששות למשך 30 יום

### שלב 6: סקירה שלאחר אירוע

תוך 5 ימי עסקים מסגירת האירוע:
- לתעד מה קרה, שורש הבעיה, ואפקטיביות התגובה
- לזהות שיפורים למניעת הישנות
- לעדכן את מרשם הסיכונים אם זוהו סיכונים חדשים
- לעדכן מדיניות זו אם נמצאו פערי תהליך
