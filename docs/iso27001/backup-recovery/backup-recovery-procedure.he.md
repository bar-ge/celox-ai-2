## 3. נהלי גיבוי

### 3.1 גיבוי יומי אוטומטי (Supabase)
- **מבצע:** תשתית Supabase (אוטומטי, ללא פעולה)
- **מתי:** יומי בחצות UTC
- **אימות:** כניסה ללוח Supabase → Project Settings → Backups לאישור שהגיבויים מופיעים
- **פורמט:** snapshot מלא של PostgreSQL

### 3.2 שחזור לנקודת זמן (PITR)
- **מבצע:** תשתית Supabase (WAL streaming רציף)
- **רזולוציה:** שחזור לכל שנייה בחלון השמירה (7 ימים)
- **מקרה שימוש:** מחיקת נתונים בשגגה, השחתה, או כופרה

### 3.3 ייצוא ידני של מסד הנתונים (ידני — חודשי)
ייצוא ידני משלים את הגיבויים האוטומטיים ומספק עותק מחוץ לפלטפורמה.

**נוהל:**
1. התקנת Supabase CLI: `npm install -g supabase`
2. התחברות: `supabase login`
3. קישור פרויקט: `supabase link --project-ref <PROJECT_REF>`
4. ייצוא סכימה + נתונים:
   ```bash
   supabase db dump --file backup-$(date +%Y%m%d).sql
   supabase db dump --data-only --file backup-data-$(date +%Y%m%d).sql
   ```
5. אימות שהקובץ לא ריק: `wc -l backup-*.sql`
6. אחסון מאובטח: כונן חיצוני מוצפן או אחסון ענן מוצפן (לא GitHub)
7. רישום הגיבוי ביומן למטה

### 3.4 גיבוי מאגר GitHub (אוטומטי)
GitHub שומר עותקים יתירים של כל המאגרים. אין צורך בפעולה נוספת. לבטיחות נוספת, אימות clone מקומי חודשי:
```bash
git clone https://github.com/bar-ge/celox-ai-2.git repo-backup-$(date +%Y%m%d)
```

## 4. נהלי שחזור

### 4.1 שחזור מגיבוי יומי של Supabase
**תרחיש:** נדרש שחזור מלא (למשל השחתת נתונים)
**שלבים:** כניסה ללוח → Project → Settings → Backups → בחירת תאריך גיבוי נקי → "Restore" (מחליף את המסד הנוכחי). ⚠️ **שחזור הרסני — כל הנתונים אחרי נקודת הגיבוי יאבדו.** להודיע ללקוחות על השחזור ותקופת אובדן הנתונים. לוודא פונקציונליות לאחר השחזור. לתעד במרשם האירועים.
**זמן שחזור משוער:** 30–60 דקות

### 4.2 שחזור לנקודת זמן (PITR)
**תרחיש:** שחזור לרגע ספציפי (למשל נתונים שנמחקו לפני שעתיים)
**שלבים:** לוח → Project → Settings → Backups → Point in Time Recovery → בחירת תאריך ושעה מדויקים → אישור. לוודא שלמות נתונים. לתעד.
**זמן שחזור משוער:** 15–30 דקות

### 4.3 שחזור מגיבוי SQL ידני
**תרחיש:** הגיבויים האוטומטיים אינם זמינים או מספקים
**שלבים:** לאתר את קובץ ה-`.sql` האחרון (אחסון מוצפן) → ליצור פרויקט Supabase חדש (אם המקורי הושמד) → שחזור סכימה: `psql postgresql://... < backup-schema-YYYYMMDD.sql` → שחזור נתונים: `psql postgresql://... < backup-data-YYYYMMDD.sql` → עדכון משתני סביבה ב-Vercel → בדיקת פונקציונליות מלאה → הודעה ללקוחות.
**זמן שחזור משוער:** 2–4 שעות

### 4.4 שחזור קוד האפליקציה
**תרחיש:** פריסת Vercel מושחתת או שינוי קוד בשגגה
**שלבים:** מאגר GitHub → מציאת ה-commit התקין האחרון (`git log --oneline`) → החזרה (`git revert <hash>` או `git checkout <hash> -- <file>`) → דחיפה ל-main → Vercel מפרס אוטומטית תוך 2 דקות → אימות בלוח Vercel.
**זמן שחזור משוער:** 10–30 דקות
